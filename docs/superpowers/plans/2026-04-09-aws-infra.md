# AWS Infrastructure Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add deploy scripts and a GitHub Actions workflow that automatically deploys the Lambda backend and S3/CloudFront frontend on every push to `main`.

**Architecture:** Two shell scripts (`scripts/deploy-backend.sh`, `scripts/deploy-frontend.sh`) each runnable locally or in CI. A single GitHub Actions workflow triggers both as parallel jobs on push to `main`, authenticating to AWS via OIDC (no stored credentials).

**Tech Stack:** Bash, AWS CLI v2, GitHub Actions, `aws-actions/configure-aws-credentials@v4`

---

## Prerequisites (One-Time Manual AWS Setup)

These steps are performed once by the developer in the AWS Console **before** the deploy scripts will work. They are not automated by this plan.

1. **Lambda function** — Name: `toolsearch-backend`, Runtime: Node.js 20.x, Handler: `backend/src/lambda.handler`. Execution role with DynamoDB access. Set env vars: `JWT_SECRET`, `SHOP_USERNAME`, `SHOP_PASSWORD`, `DYNAMODB_TABLE`, `AWS_REGION`, `ALLOWED_ORIGIN` (CloudFront URL — fill in after step 4).

2. **API Gateway** — HTTP API (v2), `$default` route → Lambda proxy integration to `toolsearch-backend`.

3. **S3 bucket** — Private (block all public access). Name it anything — you'll store it as a GitHub secret.

4. **CloudFront distribution** — Origin: S3 bucket via OAC. Default root object: `index.html`. Custom error response: 404 → `/index.html`, status 200 (required for React SPA routing). After creation, update the Lambda `ALLOWED_ORIGIN` env var to the CloudFront URL.

5. **OIDC provider in IAM** — Provider URL: `https://token.actions.githubusercontent.com`, Audience: `sts.amazonaws.com`.

6. **GitHub Actions IAM role** — Trust policy: GitHub OIDC provider scoped to `repo:robalexg/JustAToolSearchingApp:ref:refs/heads/main`. Inline permissions:
   - `lambda:UpdateFunctionCode`
   - `s3:PutObject`, `s3:DeleteObject`, `s3:ListBucket`
   - `cloudfront:CreateInvalidation`

7. **GitHub secrets** — Set in repo Settings → Secrets → Actions:
   - `AWS_ROLE_ARN` — ARN of the IAM role above
   - `AWS_REGION` — e.g. `us-east-1`
   - `LAMBDA_FUNCTION_NAME` — `toolsearch-backend`
   - `S3_BUCKET_NAME` — your bucket name
   - `CLOUDFRONT_DISTRIBUTION_ID` — your distribution ID

### Task 1: Backend deploy script

**Files:**
- Create: `scripts/deploy-backend.sh`

- [ ] **Step 1: Create `scripts/deploy-backend.sh`**

```bash
#!/usr/bin/env bash
set -euo pipefail

echo "Installing production dependencies..."
cd backend
npm ci --omit=dev
cd ..

echo "Packaging Lambda..."
zip -r lambda.zip backend/src backend/package.json backend/node_modules \
  --exclude "*/.env" \
  --exclude "*/.gitignore" \
  --exclude "*.md"

echo "Deploying Lambda..."
aws lambda update-function-code \
  --function-name "toolsearch-backend" \
  --zip-file fileb://lambda.zip \
  --region "us-east-2"

rm lambda.zip
echo "Backend deployed."
```

The zip runs from the repo root, so paths inside the zip are `backend/src/lambda.js`, `backend/node_modules/`, etc. This matches the Lambda handler setting `backend/src/lambda.handler`.

- [ ] **Step 2: Make executable**

```bash
chmod +x scripts/deploy-backend.sh
```

- [ ] **Step 3: Commit**


### Task 2: Frontend deploy script

**Files:**
- Create: `scripts/deploy-frontend.sh`

- [ ] **Step 1: Create `scripts/deploy-frontend.sh`**

```bash
#!/usr/bin/env bash
set -euo pipefail

echo "Installing dependencies..."
npm install

echo "Building frontend..."
npm run build

echo "Syncing to S3..."
aws s3 sync dist/ "s3://$S3_BUCKET_NAME" --delete --region "$AWS_REGION"

echo "Invalidating CloudFront cache..."
aws cloudfront create-invalidation \
  --distribution-id "$CLOUDFRONT_DISTRIBUTION_ID" \
  --paths "/*"

echo "Frontend deployed."
```

### Task 3: GitHub Actions workflow

**Files:**
- Create: `.github/workflows/deploy.yml`

- [ ] **Step 1: Create `.github/workflows/deploy.yml`**

```yaml
name: Deploy

on:
  push:
    branches: [main]

permissions:
  id-token: write
  contents: read

jobs:
  deploy-backend:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: '20'

      - uses: aws-actions/configure-aws-credentials@v4
        with:
          role-to-assume: ${{ secrets.AWS_ROLE_ARN }}
          aws-region: ${{ secrets.AWS_REGION }}

      - name: Deploy backend
        env:
          LAMBDA_FUNCTION_NAME: ${{ secrets.LAMBDA_FUNCTION_NAME }}
          AWS_REGION: ${{ secrets.AWS_REGION }}
        run: bash scripts/deploy-backend.sh

  deploy-frontend:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: '20'

      - uses: aws-actions/configure-aws-credentials@v4
        with:
          role-to-assume: ${{ secrets.AWS_ROLE_ARN }}
          aws-region: ${{ secrets.AWS_REGION }}

      - name: Deploy frontend
        env:
          S3_BUCKET_NAME: ${{ secrets.S3_BUCKET_NAME }}
          CLOUDFRONT_DISTRIBUTION_ID: ${{ secrets.CLOUDFRONT_DISTRIBUTION_ID }}
          AWS_REGION: ${{ secrets.AWS_REGION }}
        run: bash scripts/deploy-frontend.sh
```

- [ ] **Step 2: Commit**

```bash
git add .github/workflows/deploy.yml
git commit -m "feat: add GitHub Actions deploy workflow"
```
